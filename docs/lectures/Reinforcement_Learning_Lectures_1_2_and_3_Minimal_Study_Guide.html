Introduction to Reinforcement Learning: Complete Guide

One structured walk-through of the lecture: motivation, the framework, the mathematics, the agent’s components, and worked examples. Companion text: Sutton & Barto, Reinforcement Learning: An Introduction.

In one line: RL is the science and framework of learning to make decisions from interaction. An agent acts, observes and receives a scalar reward, and learns to maximize cumulative future reward.

011. Course context and logistics

Moodle is the communication portal; ask questions on its forum so everyone benefits. Grading is by assignments, with no exam this year. Lectures were pre-recorded because of COVID-19.

022. What is RL? Motivation from AI

The big-picture argument

  • Industrial revolution: automating repeated physical work (steam trains replacing hauling carts).
  • Digital revolution: automating repeated mental work (a calculator runs addition and multiplication that we already know how to do).
  • In both, humans first had to find the solution. The next step is letting machines find solutions themselves. We specify a problem and a goal, and the machine works out how to solve it. That is AI, and it involves learning, autonomy and decisions.

Alan Turing, 1950

In “Computing Machinery and Intelligence” Turing asked “can machines think?” and suggested that instead of programming an adult mind, we should program a child’s mind (little mechanism, many blank sheets) and subject it to education. Writing a program that can learn may be easier than writing one with all the adult’s skills. The lecturer invites you to ponder whether you agree.

Working definition of AI used here: the ability to learn to make decisions to achieve goals. It is not the only definition, but it is the central question of the course.

How RL learning differs from other learning

  • Active, not passive: your actions influence the data you see.
  • Sequential: later interactions depend on earlier ones.
  • Goal-directed: behavior has a purpose, from picking up a glass down to individual muscle signals.
  • No examples of optimal behavior: nobody tells you the exact low-level actions (muscle commands). You learn by optimizing a reward signal such as satisfaction.

Three ways to get a machine to do a task

Think of three ways to get a machine to do a task. (a) Hand-code it: a human works out the solution and writes it down (a calculator). (b) Supervised learning: a human supplies the correct answer for many examples. (c) Reinforcement learning: a human supplies only a goal (through a reward) and the machine discovers the behavior by trying things.

Why is (c) powerful? Nobody can write down the exact muscle commands for riding a bicycle, or the best move in every Go position. The lecture’s point is that most human learning is like this: someone may show you a high-level example (“write like this”) but never the low-level signals needed to carry it out. RL targets exactly that gap.

033. The agent–environment loop

An agent interacts with an environment. The agent sends actions; the environment returns observations (and rewards). The agent may be a robot in the real world, or a program in a game or on the internet. The agent’s sensors (for example a camera) define what it observes.

at time t: agent receives O_t, R_t agent emits A_t environment returns O_(t+1), R_(t+1)

The time index increments after the action is taken (convention). RL can be extended to continuous time, but this course uses discrete steps. The reward can be viewed as coming from the environment or as an internal preference over observations; either way a goal must be clearly specified.

044. Reward and the reward hypothesis

The claim: any goal can be expressed as maximizing the cumulative sum of a scalar reward. Three things are often misread:

  • It says a reward exists, not that it is easy to find. Designing a reward that is both correct and easy to optimize is a real research problem (reward design).
  • Cumulative, not immediate. “Maximize the next reward” is a much weaker goal than “maximize the total.”
  • Timing can be encoded. Compare two rewards for “reach the exit”:
Design Reward Resulting behavior
Sparse goal 0 each step, +1 on reaching the exit Any path that eventually arrives scores the same (without discounting)
Step penalty −1 each step, 0 after the exit Fewest steps wins, because each extra step costs 1

Same goal, different incentives, and the second says how fast as well as whether. In the Atari demo the reward was simply the change in score, so most steps give 0 and some give positive values.

055. Where RL applies, and two reasons to learn

Examples that RL has been successfully applied to: flying a helicopter (reward tied to air time or distance to a goal), managing an investment portfolio, controlling a power station, making a robot walk, and video and board games (+1 for a win, −1 for a loss in chess).

Important distinction: the RL problem (learning via interaction with rewards) is separate from today’s set of solution algorithms. If your problem has reward, sequential interaction and learning, you are doing RL, whether or not your algorithm is labelled “RL”. Be flexible about solutions.

Reason to learn Idea Examples
Find a solution Learn a policy, then deploy it. May include indirect steps (refuel first). Strong chess program; manufacturing robot
Adapt online Keep learning to handle unforeseen circumstances (unknown unknowns), not just to generalize widely. Chess opponent that wins about half the time or keeps you playing; robot facing new terrain or wear and tear

A small adaptive learner that tracks the world can be easier than one giant solution covering every possible case.

So, what is RL?

RL is the science and framework of learning to make decisions from interaction. It requires thinking about time and consequences, actively gathering experience, predicting the future and handling uncertainty. This makes it harder than, say, plain classification, but its scope is huge: it formalizes the AI problem. It works closely with deep learning.

Atari demo

One agent learned games such as Beam Rider and Enduro (the algorithm is DQN, covered later). Observations are raw pixels; actions are joystick inputs (directions and fire); reward is the change in score each step. The agent is not told what it controls or any strategy, and the same generic algorithm learns very different games.

066. Return, value and action value

Return

Suppose after time t the rewards are 0, 0, +1, 0, +10 and the episode ends. The (undiscounted) return is 11. The return counts only the future, because actions at time t cannot change rewards already received.

Why expectation?

The world and the agent’s choices may be random, so the return itself is random. The value is its average over that randomness: v(s) = E[G_t | S_t = s]. It answers “how good is it, on average, to be here?”

Recursive view, with numbers

The return splits as G_t = R_(t+1) + γ G_(t+1). Take γ = 0.9 and rewards 0, 0, 10 afterward:

G at last step before reward = 10 G one step earlier = 0 + 0.9 × 10 = 9 G two steps earlier = 0 + 0.9 × 9 = 8.1

This is why values “shrink” with distance from a reward. It is also why the recursion is so useful: to know the value of now, you only need the immediate reward plus the (discounted) value of the next state.

State value vs action value

v(s) averages over whatever the policy would do. q(s,a) fixes the first action to a, then follows the policy. If you know q for all actions, choosing the action with the largest q gives a better policy. This is the basis of Q-learning and DQN later.

v_π(s) = Σ_a π(a|s) · q_π(s,a)

Delayed reward and credit assignment

A reward at time t may be caused by an action many steps earlier. This is the credit assignment problem. Values handle it by passing reward information backward: a state that leads (even indirectly) to a big reward gets a big value, so actions leading there look good. Refueling a helicopter earns nothing now or even costs reward, but it keeps the larger future rewards reachable, so it has high value.

077. The discount factor

G_t = R_(t+1) + γ R_(t+2) + γ² R_(t+3) + ... 0 ≤ γ ≤ 1

γ Reward 10 steps away is worth Agent character
0 0 Myopic: only the next reward
0.5 ≈ 0.001 of its size Very short-sighted
0.9 ≈ 0.35 Plans a few tens of steps ahead
1 full value Far-sighted; can make sums infinite in non-ending tasks

Two roles: (1) a mathematical convenience that keeps infinite sums finite (with +1 per step forever, γ = 1 gives infinity); (2) a goal-shaping parameter. With “0 until the goal, then +1” and γ < 1, reaching the goal sooner gives a larger value, so the agent prefers short paths. The effective horizon is roughly 1/(1−γ) steps.

088. What is inside an agent

The framework has an environment (dynamics), a reward signal (the goal) and an agent. The agent contains:

  • Agent state (required): everything carried from one step to the next.
  • Policy (required): how actions are selected (even uniformly random counts).
  • Value function estimate (optional but common).
  • Model (optional): a prediction of the environment’s dynamics.

099. State, history and the Markov property

Use a concrete picture: you playing a video game.

  • Environment state: everything the game engine stores (all enemy positions, hidden timers, random-number seeds). You never see it all.
  • Observation: the screen you see right now.
  • History: every screen, button press and score change since you started.
  • Agent state: your mental summary: “enemy came from the left, I have two lives, power-up active.” It is what you carry forward, and it should be built from history only.

The agent state is defined by an update rule: new state = u(old state, action, reward, new observation). Because of that, the agent never needs to store the whole history, only a running summary.

Full observability

If the observation is the environment state, the agent state can simply be the observation and no memory is needed. This is the special case that theory often assumes because it is easy to reason about, but it is rare in practice.

Meaning: “the future depends on the past only through the present state.” If you know S_t, the rest of the history adds no predictive information about the next reward and next state.

p(r, s' | S_t = s) = p(r, s' | H_t) (probability of the next reward r and next state s' given the state equals that given the whole history)

Examples: a chess position is Markov (the board tells you everything needed to continue; how you got there does not matter, ignoring special rules such as repetition and castling rights). The velocity-free screenshot of a ball in Pong is not Markov, because you cannot tell which way the ball is moving, so you need at least two frames. That is exactly why Atari agents stack frames.

Why it matters

Algorithms with the Markov assumption (value recursion, Bellman equations, MDP theory) only work cleanly if the state really summarizes the past. If it does not, the agent confuses different situations that look identical, which is called perceptual aliasing.

1010. Partial observability and the maze

In a POMDP the agent sees an observation that is only a slice of the true state. The lecture’s maze: the agent sees just the 3×3 cells around itself. Two corridor spots can produce the same 3×3 view.

  1. Goal: top-left. Start: top-right.
  2. At the start, shortest path to the goal means going down.
  3. At the second, look-alike spot, shortest path means going up.
  4. A policy that is a function of the current observation must output one action for the identical view, so it must be wrong in at least one place.

Candidate fixes

Agent state Works? Issue
Current observation only No Aliasing, as shown
Full history Yes (always Markov) Grows without bound
Last two observations Sometimes Fails with random policy or noisy moves; works if the policy never walks between the ambiguous cells in the confusing order
Learned recurrent summary Often well enough Needs to be learned; approximate

The moral: you rarely get a perfect Markov state, and you do not need one. What you need is a state good enough to support good decisions and value estimates.

The state update function

S_(t+1) = u(S_t, A_t, R_(t+1), O_(t+1))

This recursive form covers every case above: concatenating everything gives the full history, keeping only the newest observation gives “state = observation”, and a two-slot buffer drops the oldest observation each step. We want u to compress the stream into a fixed-size state that keeps what matters for acting.

1111. Policies

A policy maps agent state to action: deterministic a = π(s), or stochastic π(a|s), a probability distribution over actions. It is a function of the agent state, never of hidden environment state.

Why stochastic policies?

  • They give built-in exploration: trying actions that currently look worse in order to learn more (the topic of the next lecture).
  • They are smooth to optimize: small changes to probabilities give small changes in behavior, which is what policy-gradient methods use.
  • They include the deterministic case as a special case.

What “value of a policy” means

Writing v_π conditions on a function, not a fixed list of actions: at every future step the action is chosen by π after seeing the state reached, which may differ from run to run. Two policies can then be compared state by state, and a better one can be built from the values of the current one (evaluate, then improve). Later lectures turn this loop into real algorithms.

1212. Value functions and the Bellman equations

Start with v_π(s) = E[G_t | S_t = s] and substitute G_t = R_(t+1) + γ G_(t+1):

v_π(s) = E[ R_(t+1) + γ v_π(S_(t+1)) | S_t = s ]

Read it as: value now = expected immediate reward + discounted value of where I land. This is a consistency condition: the values of neighbouring states must agree with each other.

Tiny example

States X → Y → Terminal. Reward +1 on X→Y, +2 on Y→Terminal, γ = 0.9, one action only.

v(Terminal) = 0 v(Y) = 2 + 0.9 × 0 = 2 v(X) = 1 + 0.9 × 2 = 2.8

The optimality version

v*(s) = max_a E[ R_(t+1) + γ v*(S_(t+1)) | S_t = s, A_t = a ]

The only change is “max over actions” instead of “follow policy π.” Because the unknown v* appears on both sides, algorithms can start with a guess, repeatedly apply the right-hand side, and converge to v*. That idea, fixed-point iteration on the Bellman equation, is behind dynamic programming, Q-learning and DQN in later lectures.

From values to behavior

Given q*, the optimal policy is just: in each state take the action with the highest q*. This is why a good value function is so valuable, and also why approximate values can still give very good policies.

1313. Models of the environment

Model

A model predicts what the environment does next: a transition model p(s'|s,a) and a reward model E[R|s,a]. Unlike a value function, a model does not directly give a policy; you need planning on top. Model variants include distribution models (full distribution), expectation models, and sample models (a plausible next state). The right choice is not settled.

A value function says how good things are; it hides how the world works. A model says how the world works; to get behavior from it you still must plan (search or simulate). Value-based methods act immediately but can’t answer “what if”; model-based methods can imagine futures but depend on an accurate model. In the lecture’s maze example a learned model missed an unexplored corner, so planning inside it can only solve what it has seen.

Simple maze illustration

Start at the left, goal at the right, reward −1 per step, actions N/E/S/W, state = position (fully observable). The optimal policy is the shortest path; its value rises by 1 in magnitude for each step further from the goal (−1, −2, and so on). A learned model can be imperfect, for example missing part of the maze it has not explored; policies and values can also be imperfect.

1414. Agent categories

Two independent questions classify an agent: what does it learn (value, policy, both) and does it have a model?

Type Components How it acts Notes
Value-based Value function only Policy read off values, e.g. pick the action with the highest q (mostly) The Atari DQN agent
Policy-based Explicit policy only Samples from π directly Learns without values; example next lecture
Actor-critic Policy (actor) + value (critic) Actor acts, critic scores its choices and guides updates Common in deep RL
Model-free Policy and/or value, no dynamics model Acts from learned values/policy Simple; needs plenty of real experience
Model-based Dynamics model, optionally policy/value Plans with the model (or mixes planning with a policy) Can “imagine”; limited by model accuracy

A value function does model something (expected cumulative reward), but in RL vocabulary “model” means a model of the environment’s dynamics, so a pure value agent is called model-free. These labels are conventions, not a perfect division.

1515. Prediction, control, learning and planning

Prediction vs control

Prediction evaluates the future for a given policy (for instance, the value of the uniformly random policy). Control optimizes the future by finding the best policy. They are linked: π* is the policy whose value is highest, so values rank policies, and good predictions let you improve control.

Learning vs planning

Learning Planning
Input New experience from the interaction loop A model (given or learned); no new experience
Nature Absorbs data into values, policy or model Internal computation that improves policy or predictions

Both can run together in one agent. Caveat: planning in a learned model can exploit its errors. If the model wrongly believes a wall has a hole, the shortest path goes through that hole and the resulting policy fails in the real world.

Is prediction enough?

Sutton often argues that predictions are a rich form of knowledge: if you could predict everything, what else would you need? The lecture’s hint is that with imperfect approximation it still helps to store predictions and policies (skills) separately, since knowing the world does not automatically tell you what to do.

1616. Deep reinforcement learning

Every component is a function: policy (state→action probabilities), value (state→expected return), model (state, action→next state, reward), and the state update u. Neural networks are strong function learners, and combining them with RL is deep RL.

Why it is not plug-and-play

  • Correlated data: a robot in one room produces strongly similar consecutive samples, while supervised learning assumes roughly independent examples.
  • Non-stationary targets: when the policy changes, the value function of the current policy changes with it, so the learning target keeps moving.

Later lectures cover the remedies; the point here is that deep RL is a research area of its own at the intersection of the two fields.

Atari (DQN)

Action Joystick directions plus fire
Reward Change in score each step (mostly 0, sometimes positive)
Prior knowledge None: not told what the player is, the rules or any strategy

Because the algorithm is generic, the same agent learns very different games. It is a value-based, model-free agent.

The 5×5 grid world (Sutton & Barto), γ = 0.9

  • Bumping into a wall: −1. Most other steps: 0.
  • Any action in A: +10 and teleport to A′. Any action in B: +5 and teleport to B′.

Prediction (uniform random policy). v(A) ≈ 8.8, below 10 because after the +10 the random agent soon bumps into walls and collects −1 penalties. v(A′) ≈ −1.3 since A′ sits at the edge and the walk back toward A is unproductive. Bottom-left states are strongly negative because a random agent repeatedly hits walls.

Control (optimal policy). All values become positive since an optimal agent never bumps into a wall. Even though B is closer to B′, looping A → A′ → … → A pays +10 per loop, which beats the +5 loop of B, so almost every state heads to A. Only the top-right corner jumps into B, because walking around B to reach A would take longer than being teleported to B′ and walking on to A. These conclusions are hard to see by inspection, but learning and planning algorithms find them automatically.

Learned locomotion

Simulated 2D and 3D bodies learned to run, jump and climb obstacles with one reward: speed in a single direction. They sensed the terrain through simplified vision and proprioception (sensing their own limbs). No gait was hand-designed, and the same learner worked across body types and terrains.

Lecture 2: Exploration and Exploitation

This chapter develops the exploration–exploitation problem through multi-armed bandits. It introduces action-value estimates, regret, simple greedy strategies, stochastic policies, optimism, confidence bounds and Bayesian sampling. The focus is on why an agent explores and how uncertainty can guide its choices.

011. The exploration–exploitation dilemma

At each decision, an agent faces two competing possibilities:

  • Exploitation: choose the action that currently appears to have the highest expected reward, making use of what has already been learned.
  • Exploration: choose an action partly to gain information, even if its estimated reward is currently lower.

Pure exploitation can get stuck with a misleading early estimate. Pure exploration wastes opportunities by repeatedly testing actions instead of using what has been learned. A successful learner needs a balance.

Intuition: Imagine choosing between several cafés. You can keep visiting the one you already like, or occasionally try another café that might turn out to be even better.

The key difficulty is that the agent usually does not know the true reward distribution of each action. It must learn those properties while making decisions.

022. Multi-armed bandits

A multi-armed bandit is a simplified sequential decision problem. There are several actions (often pictured as slot-machine arms). At each time step the agent chooses one action and receives a reward. The reward distribution for an action is initially unknown.

Basic setup

  • There are \(k\) available actions, indexed by \(a\in\{1,\ldots,k\}\).
  • Choosing action \(a\) produces a reward \(R_t\) drawn from that action’s reward distribution.
  • The expected reward of action \(a\) is its true action value, often written \(q_*(a)\).
  • The agent observes the reward it receives, updates its estimate, and chooses again.

Unlike the full reinforcement-learning setting introduced in Lecture 1, the basic bandit has no changing state and no long sequence of state transitions to plan through. It isolates the problem of choosing among uncertain actions.

Why the bandit is useful

Although simple, bandits capture a central RL challenge: actions both earn reward and produce information. This makes them a useful first setting for studying exploration strategies.

033. Action values and regret

The action value \(q_*(a)\) is the expected reward obtained by choosing action \(a\):

q*(a) = E[R_t | A_t = a]

Because the true value is unknown, the agent maintains an estimate, written \(Q_t(a)\). A straightforward estimate is the sample average of rewards received after choosing that action:

Q_t(a) = (sum of rewards observed for a) / (number of times a was selected)

Each new reward can update the estimate. If action \(a\) has been selected \(N_t(a)\) times, an incremental update is:

Q_new(a) = Q_old(a) + [R - Q_old(a)] / N_new(a)

This update moves the estimate toward the latest reward without storing the full reward history.

Regret

Regret measures the reward lost by not always choosing the best action in hindsight. If the best true action value is \(q_*(a^*)\), the expected one-step regret from choosing \(A_t\) is:

q*(a*) - q*(A_t)

Cumulative regret adds this loss over decisions. An exploration strategy may accept some short-term regret to discover a better action and reduce regret over the longer run.

044. Greedy and ε-greedy methods

Greedy action selection

A greedy agent always chooses an action with the largest current estimate:

A_t = argmax_a Q_t(a)

This exploits current knowledge, but it may never discover that another action is better. If early rewards make a poor action look unusually good, the agent can repeatedly select it and stop gathering evidence about alternatives.

ε-greedy action selection

The ε-greedy strategy adds occasional random exploration:

  • With probability \(1-\varepsilon\), choose a greedy action.
  • With probability \(\varepsilon\), choose an action at random.

Here, \(\varepsilon\) controls the exploration rate. If \(\varepsilon=0\), the strategy is greedy. A larger \(\varepsilon\) means more exploration.

StrategyWhat it doesMain limitation
GreedyAlways picks the current highest estimateCan miss better actions because it does not explore deliberately
ε-greedyUsually exploits, sometimes explores randomlyRandom exploration may spend trials on clearly poor actions

ε-greedy is simple and often effective as a baseline. It does not, however, use the degree of uncertainty about each action to decide which alternative is most informative.

055. Policy gradients and softmax

Instead of estimating action values and selecting the largest one, an agent can learn a stochastic policy directly. A policy assigns a probability to each action.

Softmax action preferences

One way to construct a policy is to maintain a preference \(H_t(a)\) for each action and convert preferences into probabilities with softmax:

π_t(a) = exp(H_t(a)) / sum_b exp(H_t(b))

Higher preferences produce higher probabilities, but actions with lower preferences can still be selected. This gives a graded form of exploration rather than the uniform random exploration used by ε-greedy.

Preferences are not themselves reward estimates. They are parameters that determine the policy’s action probabilities.

Policy-gradient idea

A policy-gradient method adjusts policy parameters in a direction expected to increase reward. It can learn how likely actions should be, rather than first learning a separate value estimate for every action and then taking an argmax.

066. REINFORCE and the log-likelihood trick

REINFORCE is a policy-gradient approach. Its central idea is to increase the probability of actions associated with good outcomes and decrease the probability of actions associated with poor outcomes.

Why the log probability appears

Directly differentiating a sampled action is difficult because the action is discrete. The log-likelihood identity rewrites a probability gradient in a useful form:

∇θ πθ(a) = πθ(a) ∇θ log πθ(a)

Equivalently, dividing by the policy probability gives:

∇θ log πθ(a) = ∇θ πθ(a) / πθ(a)

This lets the gradient of an expected reward be expressed using sampled actions and the gradient of their log probabilities. A typical REINFORCE update has the form:

θ ← θ + α G_t ∇θ log πθ(A_t)

Here, \(\alpha\) is a step size and \(G_t\) is the sampled return or reward signal associated with the action. The update increases the log probability of actions followed by high returns. In a one-step bandit, the reward itself plays the role of the return.

Interpretation: if an action produces a better-than-expected outcome, move the policy toward choosing it more often; if it produces a poor outcome, move away from it.

077. Optimism under uncertainty

Another approach to exploration is to make uncertain actions look temporarily attractive. This is called optimism in the face of uncertainty.

Rather than choosing only by the current average reward estimate, the agent adds an exploration bonus. Actions that have been tried rarely, and therefore remain uncertain, can receive a larger bonus.

This creates a useful behavior: an action may be selected not because its estimated reward is already high, but because there is a meaningful chance that its true reward is high and the agent has not tested it enough.

088. Upper Confidence Bound (UCB)

Upper Confidence Bound (UCB) formalizes optimism by adding a confidence-based bonus to the estimated action value. A common bandit UCB rule is:

A_t = argmax_a [ Q_t(a) + c √(ln t / N_t(a)) ]

  • \(Q_t(a)\): estimated mean reward for action \(a\).
  • \(N_t(a)\): number of times action \(a\) has been selected.
  • \(t\): current decision count.
  • \(c\): parameter controlling the strength of exploration.
  • The square-root term is the exploration bonus.

When an action has been selected only a few times, its bonus is large. As it is sampled more often, the bonus shrinks. The logarithm of time allows the exploration bonus to respond to the overall growth in the number of decisions.

UCB therefore balances estimated reward and uncertainty in a targeted way: it explores actions with high plausible upside rather than choosing random actions indiscriminately.

099. Hoeffding’s inequality and the UCB idea

Hoeffding’s inequality is a concentration result: for bounded independent samples, it gives a bound on how far a sample average is likely to be from its true expected value.

In bandit reasoning, this supports the idea of an upper confidence estimate: a sample mean plus a term that accounts for how many observations have been collected. More observations generally make the uncertainty interval narrower.

The UCB strategy uses the upper side of such an estimate as an optimistic score. It selects the action with the highest upper confidence bound, giving preference to actions whose mean may be high or whose estimate is still uncertain.

Big picture: the confidence bonus is not an arbitrary reward bonus. It represents uncertainty in the estimate, with the number of samples controlling how much uncertainty remains.

1010. Bayesian bandits

A Bayesian bandit represents uncertainty about an action’s reward parameter with a probability distribution, called a posterior distribution. Before observing rewards, the agent has a prior belief. Each observed reward updates that belief using Bayes’ rule.

This differs from keeping only a point estimate such as a sample mean. A posterior distribution can express both a central estimate and how uncertain the agent remains.

Prior, likelihood and posterior

  • Prior: belief about an action’s reward parameter before new data.
  • Likelihood: how probable the observed data are under a candidate parameter value.
  • Posterior: updated belief after combining prior and observed data.

As evidence accumulates, the posterior typically becomes more concentrated. The agent can use this uncertainty directly when deciding which action to try next.

1111. Thompson sampling

Thompson sampling is a Bayesian exploration strategy. At each decision, the agent samples a plausible reward parameter (or action value) from each action’s posterior belief and chooses the action with the highest sampled value.

  1. Maintain a posterior distribution for each action.
  2. Sample one plausible value for every action from its posterior.
  3. Choose the action with the largest sampled value.
  4. Observe its reward and update that action’s posterior.
  5. Repeat.

An action with a high posterior mean is often selected. An uncertain action can also be selected because some posterior samples may place its true value high. As uncertainty decreases, the sampling decisions increasingly reflect the accumulated evidence.

Unlike ε-greedy, Thompson sampling does not explore by selecting a uniformly random action with a fixed probability. Its exploration is shaped by the posterior uncertainty.

1212. Planning to explore

Exploration can also be considered as a decision whose value comes from what the agent will learn and how that information may improve later decisions. This is sometimes described as planning to explore or value of information.

An exploratory action may have a low immediate reward but reveal information that changes future choices. Its total value therefore includes both immediate reward and the possible benefit of better-informed decisions later.

This perspective connects bandit exploration to the broader sequential RL setting from Lecture 1, where actions influence not only the next reward but also future states and opportunities.

Lecture 3: Markov Decision Processes & Dynamic Programming

Lectures 1 and 2 introduced the agent–environment interaction and the exploration–exploitation problem in bandits. This lecture generalizes that setting to sequential environments: the agent observes a state, chooses an action, receives a reward, and moves to a new state. Because today's action can affect future states and rewards, the agent must reason about long-term consequences.

The lecture assumes a fully observable environment for its main exposition and focuses mostly on finite, discrete state and action spaces. It introduces methods that assume the agent has access to the true model of the environment.

011. From bandits to sequential reinforcement learning

A bandit can be viewed as a very small RL problem with one state and multiple actions. A full MDP adds a sequence of states: actions influence both the immediate reward and which state the agent encounters next.

  • The agent chooses actions according to a policy.
  • The environment responds with a reward and a next state.
  • The process repeats over time, so decisions can have long-lasting consequences.
  • The agent may use a policy, a value function, and/or a model of the world to decide what to do.

The lecture's first family of solution methods assumes the true environment model is known. These are Dynamic Programming (DP) methods. Later sample-based approaches can relax the requirement for a known model.

022. Markov Decision Processes (MDPs)

A Markov Decision Process formalizes the agent–environment interaction. In the joint-transition formulation, an MDP is described by the tuple:

MDP: (S, A, P, γ)

where the transition kernel P specifies the joint distribution of next state and reward given the current state and action.

  • S: set of possible states.
  • A: set of available actions.
  • P(s′, r | s, a): probability of reaching next state s′ and receiving reward r after taking action a in state s.
  • γ: discount factor, between 0 and 1, controlling the relative weight of future rewards.

The transition kernel is also called the dynamics of the problem. It tells us what can happen after an action and how likely each outcome is.

Equivalent marginal formulation

The lecture also presents an equivalent representation that separates state transitions and expected rewards:

  • P(s′ | s,a) = Σ_r P(s′,r | s,a) — probability of the next state, marginalizing over rewards.
  • r(s,a) = E[R | s,a] — expected immediate reward given the current state and action.

These formulations are equivalent; they simply package the transition and reward information differently. In the joint form, reward may depend on the resulting next state. In the marginal form, the reward supplied is the expected reward conditional on the current state and action.

033. The Markov property

The defining idea behind an MDP is the Markov property: once the current state is known, the history before that state is not needed for predicting the future.

P(Sₜ₊₁, Rₜ₊₁ | Sₜ, Aₜ, history) = P(Sₜ₊₁, Rₜ₊₁ | Sₜ, Aₜ)

In words, the current state summarizes all information from the past that is relevant to predicting the next state and reward. The state is therefore a sufficient statistic of the history for this prediction problem.

It does not mean that the future is independent of the action. The action is chosen at the current time and influences the distribution of the next state and reward.

How to check a Markov statement

  • Past history can be removed from the conditioning once the current state and action are known.
  • Future quantities are predicted from the current state and action.
  • Information about an action taken now cannot be discarded when predicting what happens next.

The lecture notes that even partially observable problems can sometimes be represented as MDPs by using an appropriate state that contains the relevant history or belief information.

044. Example: the cleaning robot

The lecture uses a cleaning robot example to make an MDP concrete. The robot collects soda cans and has two battery states:

  • High battery
  • Low battery

It has three actions:

  • Wait: remain available for someone to put a can into the bin.
  • Search: actively look for cans. This has a higher expected reward than waiting, but can consume battery.
  • Recharge: restore the battery from low to high.

Searching from the high-battery state can lead back to high battery with probability α, or to low battery with probability 1−α. The low-battery search transition has an additional possibility of a penalty (−3), occurring with probability 1−β; with probability β the robot receives the search reward.

This example illustrates why the joint transition kernel can be useful: the reward may depend on the next state. If using the marginal formulation, the expected reward must be computed by averaging over the possible outcomes.

An MDP can also be drawn as a directed graph: states are nodes, and arrows represent possible transitions, annotated with their probabilities and associated rewards.

055. Returns and discounting

The return is the total reward accumulated from a point in time onward. The lecture introduces three common objectives:

Return typeDefinition / ideaTypical use
UndiscountedSum of future rewards without discountingFinite-horizon episodic tasks
DiscountedFuture rewards weighted by powers of γFinite- and infinite-horizon tasks
Average rewardLong-run average reward per time stepContinuing infinite-horizon tasks

The lecture focuses on discounted return:

Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + …

For an infinite horizon: Gₜ = Σₖ₌₀∞ γᵏ Rₜ₊ₖ₊₁

The discount factor γ is between 0 and 1:

  • γ close to 0: immediate rewards dominate. The objective is myopic.
  • γ close to 1: delayed rewards retain more weight. The objective is more far-sighted.
  • γ = 0: only the immediate reward contributes.
  • γ = 1: discounted return becomes undiscounted return, when that sum is well-defined.

Discounting can reflect a real preference for earlier rewards, uncertainty about reaching the distant future, or mathematical convenience. In continuing cyclic problems, undiscounted infinite sums may be unbounded; discounting can help keep the objective well behaved.

066. Policies and value functions

A policy specifies how the agent behaves. A stochastic policy assigns a probability to each action in each state:

π(a | s) = P(Aₜ = a | Sₜ = s)

A deterministic policy selects one action for each state, often written a = π(s).

State-value function

The value of a state under policy π is the expected return starting from that state and then following π:

Vπ(s) = Eπ[Gₜ | Sₜ = s]

Action-value function

The action value is the expected return when starting in state s, taking action a first, and following π thereafter:

Qπ(s,a) = Eπ[Gₜ | Sₜ = s, Aₜ = a]

The two are connected by averaging action values under the policy:

Vπ(s) = Σₐ π(a|s) Qπ(s,a)

So Vπ tells us how good it is to be in a state when following π, while Qπ tells us how good it is to take a particular action there and then continue with π.

077. Optimal values and policies

The optimal state-value function is the best value achievable from each state over all possible policies. The optimal action-value function is defined similarly, after taking a specified first action:

V*(s) = maxπ Vπ(s)

Q*(s,a) = maxπ Qπ(s,a)

An optimal policy π* is at least as good as every other policy in every state. The lecture describes this as policy dominance: π dominates π′ if Vπ(s) ≥ Vπ′(s) for every state s.

  • An optimal policy exists for the MDP setting considered in the lecture.
  • All optimal policies share the same optimal value function and optimal action-value function.
  • There is always a deterministic optimal policy, although other optimal policies may be stochastic.
  • If Q* is known, an optimal policy is obtained by acting greedily with respect to Q*.
π*(s) ∈ argmaxₐ Q*(s,a)

088. Bellman expectation equations

The Bellman expectation equations express the recursive structure of value functions under a fixed policy. The return can be split into the immediate reward plus the discounted return from the next state.

State-value form

Vπ(s) = Σₐ π(a|s) Σₛ′,ᵣ P(s′,r|s,a) [r + γVπ(s′)]

First average over the action chosen by policy π, then over the possible next-state/reward outcomes.

Action-value form

Qπ(s,a) = Σₛ′,ᵣ P(s′,r|s,a) [r + γ Σₐ′ π(a′|s′)Qπ(s′,a′)]

Here the first action is fixed as a; after the transition, the next action is selected according to π. The value at the next state is the policy-weighted average of its action values.

These equations are recursive because the value at the current time is expressed using values at the next time step.

099. Bellman optimality equations

The Bellman optimality equations describe the optimal value functions. The key difference from the expectation equations is that the policy average over the next action is replaced by a maximum: after reaching the next state, the agent chooses the best available action.

Optimal state-value form

V*(s) = maxₐ Σₛ′,ᵣ P(s′,r|s,a) [r + γV*(s′)]

Optimal action-value form

Q*(s,a) = Σₛ′,ᵣ P(s′,r|s,a) [r + γ maxₐ′ Q*(s′,a′)]

The maximization makes the optimality equations nonlinear in general. This is why the direct linear-system solution used for policy evaluation does not transfer straightforwardly to control.

1010. Prediction vs. control

The lecture distinguishes two fundamental RL problem classes:

ProblemGivenGoalValue target
Prediction / policy evaluationA fixed policy πDetermine how well that policy performsVπ or Qπ
ControlAn MDP, with no fixed policy to evaluateFind optimal behaviorV* or Q*, then π*

Prediction asks, “How good is this behavior?” Control asks, “What is the best behavior?” Control is more demanding because the policy itself must be improved.

The lecture illustrates policy evaluation with a three-state chain and two actions. It considers a policy that always chooses one action and a uniformly random policy, with discount factors 0.9 and 0. This example is intended to practice reading an MDP diagram, applying the reward specification, and computing state values.

1111. Matrix solution to policy evaluation

For a finite MDP and fixed policy π, the Bellman expectation equations for all states can be collected into a linear system:

vπ = rπ + γPπvπ

Rearranging gives: vπ = (I − γPπ)⁻¹ rπ

  • vπ: vector containing the value of every state under π.
  • rπ: expected immediate reward vector under π.
  • Pπ: state-transition matrix when actions are selected according to π.
  • I: identity matrix.

The transition matrix averages the environment dynamics over the policy's action probabilities. The reward vector similarly averages immediate rewards under the policy.

This gives an exact solution when the required inverse exists, but matrix inversion is computationally expensive for large state spaces. The lecture notes cubic complexity for a standard dense solution, making it practical mainly for small problems. Iterative evaluation and other methods are used for larger state spaces.

1212. Dynamic Programming

Dynamic Programming is a family of algorithms for computing value functions and optimal policies when the true MDP model is known. The lecture emphasizes a recurring pattern:

  1. Policy evaluation: estimate the value of the current policy.
  2. Policy improvement: use those values to construct a better policy.

Repeating these steps leads to policy iteration. A different approach, value iteration, applies the Bellman optimality update directly.

The DP algorithms introduced here use the full model: they average over the possible successor states and rewards rather than relying on a single sampled transition.

1313. Iterative policy evaluation

Instead of solving the matrix equation directly, policy evaluation can be performed by repeatedly applying the Bellman expectation update. Start with an initial estimate for every state, such as zero, and update all states using the previous iteration's values:

Vₖ₊₁(s) = Σₐ π(a|s) Σₛ′,ᵣ P(s′,r|s,a)[r + γVₖ(s′)]

Continue until the values change by less than a chosen tolerance (or, in the exact mathematical description, until the update no longer changes the values). Under the appropriate conditions discussed in the course, including γ less than 1, the procedure converges to Vπ.

Grid-world illustration

The lecture uses a grid world with terminal states, a reward of −1 for each transition, discount factor 1, and a uniformly random policy over the available directions. The values are initialized to zero.

  • At the first update, each nonterminal state's value becomes −1 because the next-state estimates are all initially zero.
  • At later updates, each state's value reflects the −1 immediate reward plus the average value of the states reachable under the random policy.
  • Repeated updates propagate the cost of taking steps through the grid until the values converge.

The converged values evaluate the random policy. Acting greedily with respect to these values can then produce a much better policy, which motivates policy improvement.

1414. Policy improvement and policy iteration

Greedy policy improvement

Given the value function for a policy π, define a new policy that chooses an action maximizing the one-step lookahead value:

πnew(s) ∈ argmaxₐ Σₛ′,ᵣ P(s′,r|s,a)[r + γVπ(s′)]

The policy improvement principle says that this greedy policy is at least as good as the original policy in every state. Intuitively, if a different action has a better one-step lookahead according to the evaluated values, taking that action offers an opportunity to improve; if the maximizing action is the same, the policy need not change.

Policy iteration algorithm

  1. Initialize a policy π.
  2. Evaluate it to obtain Vπ (or Qπ).
  3. Improve the policy, typically by acting greedily with respect to the evaluated values.
  4. If the policy changes, evaluate the new policy and repeat.
  5. Stop when the greedy improvement step returns the same policy. The stable policy is optimal under the conditions considered.

Policy iteration alternates between evaluation and improvement. The lecture illustrates it with a car-rental problem involving two locations, limited car movement, movement costs, rental rewards, and stochastic requests and returns modeled with Poisson distributions. Although the dynamics are too involved to solve by inspection, policy iteration reaches a stable policy after a small number of iterations in the presented example.

Do we need exact policy evaluation every time?

Not necessarily. If the value estimate is being used to improve the policy, it may be wasteful to evaluate the current policy all the way to convergence before improving it. The lecture uses this observation to motivate value iteration.

1515. Value iteration

Value iteration combines policy evaluation and improvement into a single update. It applies the Bellman optimality equation repeatedly:

Vₖ₊₁(s) = maxₐ Σₛ′,ᵣ P(s′,r|s,a)[r + γVₖ(s′)]

Instead of averaging over the actions of a fixed policy, each update takes the best action according to the current lookahead values. This can be understood as an extreme form of truncated policy evaluation: perform one backup and then immediately make a greedy improvement.

  1. Initialize V₀(s), often to zero.
  2. For each state, update using the maximum over actions and the full model's expected next-step return.
  3. Repeat until the values stabilize within a tolerance.
  4. Extract a policy by acting greedily with respect to the converged values.

The lecture's grid example uses a −1 reward per transition and a terminal state. The algorithm propagates values backward from the terminal state, favoring actions that reach termination in fewer steps. Once the values satisfy the Bellman optimality equation, greedy action selection yields an optimal policy.

1616. Asynchronous Dynamic Programming and sample backups

The synchronous DP methods described so far update every state at every iteration, often maintaining separate old and new value tables. This can be costly for large state spaces.

Asynchronous updates

Asynchronous Dynamic Programming updates states individually, in a chosen order, rather than updating all states in lockstep. The lecture describes several examples:

  • In-place value iteration: store one value table and immediately reuse values that have already been updated, rather than keeping separate copies for each iteration.
  • Prioritized sweeping: select states according to a priority measure, such as the magnitude of their Bellman error. States with larger errors are updated first. This can use a priority queue and information about predecessor states.
  • Real-time Dynamic Programming: focus computation on states relevant to the agent's current situation and likely near-future decisions.

The lecture states that asynchronous updates can converge when states continue to be visited with nonzero probability under the relevant conditions.

Full backups vs. sample backups

Standard DP uses full backups: it considers all possible successor states (and relevant actions) using the model. For very large state or action spaces, even one full backup can be expensive.

A sample backup instead uses an observed transition such as (s, a, r, s′) to update an estimate. This avoids requiring the full transition model and leads toward model-free, sample-based methods. The lecture previews Monte Carlo and Temporal-Difference approaches, including Q-learning and SARSA, as topics to be developed in subsequent lectures.
